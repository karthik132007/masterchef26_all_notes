discovery answers “where is the service?”; load balancing answers “which instance should I call?”

today's outcome

Register services with Eureka, call them by a logical service name, and separate service discovery from instance selection.

the problem with fixed URLs

http://localhost:8081/products/1

A physical host and port are deployment details. If Product Service runs on ports 8081, 8082, and 8083, callers should not hard-code one instance.

eureka's role

Product Service :8081 ─┐
Product Service :8082 ─┼─ register → Eureka Server
Product Service :8083 ─┘

Order Service → ask Eureka for PRODUCT-SERVICE instances

Eureka is a service registry. Clients register metadata such as service name, host, port, and health information.

Read the official Spring Cloud Netflix reference before choosing the compatible Spring Cloud release train for your Spring Boot version.

three applications

  1. Create a Eureka Server application with the Eureka Server starter and enable the server.
  2. Add the Eureka Client starter to Product Service and Order Service.
  3. Give each service a stable name such as PRODUCT-SERVICE and configure the registry URL.

Keep the registry address in configuration. Do not put a production registry URL directly into business code.

discovery versus load balancing

PRODUCT-SERVICE
       ↓
Eureka returns 8081, 8082, 8083
       ↓
Spring Cloud LoadBalancer chooses one
       ↓
Order Service sends the request
⭐ interview distinction
Eureka discovers instances. LoadBalancer selects an instance. They solve different problems.

logical service names

PRODUCT-SERVICE/products/1

The logical name decouples the caller from physical locations. The client library resolves that name and applies the configured load-balancing strategy.

health and failure

  • A registered service can still be unhealthy; registration is not the same as a successful request.
  • Use health checks and timeouts.
  • Remove failed instances from traffic and restore them only after they recover.

practice

  1. Register two Product Service instances with Eureka.
  2. Call Product Service from Order Service using its logical name.
  3. Stop one instance and observe what changes in the registry and request behavior.
