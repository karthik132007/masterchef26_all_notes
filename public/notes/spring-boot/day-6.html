today's outcome

Make the student API safer and more production-shaped with externalized configuration, validation, consistent errors, and transaction boundaries.

configuration without secrets

spring.datasource.url=jdbc:postgresql://localhost:5432/classroom
spring.datasource.username=classroom
spring.datasource.password=${DB_PASSWORD}
server.port=8081

Keep environment-specific values outside source control. Use application-dev.properties and application-prod.properties only for non-secret defaults; inject secrets through environment variables or a secret manager.

See the official externalized configuration documentation.

profiles

spring.profiles.active=dev

// or at startup
java -jar app.jar --spring.profiles.active=prod

Profiles select configuration and beans for an environment. They are not a security boundary; secrets still need secure storage.

validate at the boundary

public record StudentRequest(
    @NotBlank String name,
    @NotBlank @Email String email,
    @NotBlank @Size(max = 80) String branch
) {}

@PostMapping
public ResponseEntity<StudentResponse> create(
        @Valid @RequestBody StudentRequest request) {
    return ResponseEntity.status(HttpStatus.CREATED)
        .body(service.create(request));
}

Validation belongs at the boundary so invalid input does not travel through the service and persistence layers.

one error shape

@RestControllerAdvice
public class ApiExceptionHandler {
    @ExceptionHandler(StudentNotFoundException.class)
    ResponseEntity<ApiError> notFound(
            StudentNotFoundException exception,
            HttpServletRequest request) {
        return ResponseEntity.status(HttpStatus.NOT_FOUND)
            .body(new ApiError(404, exception.getMessage(), request.getRequestURI()));
    }
}

transactions

A transaction groups related database changes. If a later operation fails, the database can roll back the earlier changes.

@Transactional
public Enrollment enroll(Long studentId, Long courseId) {
    Student student = studentRepository.getReferenceById(studentId);
    Course course = courseRepository.getReferenceById(courseId);
    return enrollmentRepository.save(new Enrollment(student, course));
}

Keep transactions around a business operation, not around an entire web request that performs slow external calls.

trade-off table

ChoiceUse this when
JPAYour domain maps naturally to entities and you value productive CRUD.
JDBCYou need direct SQL control or highly specialized queries.
Lazy loadingThe relationship is not needed for every request.
DTOsYour API contract should be independent from the database model.

practice

  1. Add validation for every create/update field.
  2. Return the same error shape for not found, validation, and duplicate email errors.
  3. Demonstrate rollback by forcing the second operation in a transaction to fail.
