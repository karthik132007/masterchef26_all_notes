production checklist

  • Use DTOs and validate request data at the HTTP boundary.
  • Keep business rules in services, not controllers.
  • Keep database credentials and environment values outside Git.
  • Use transactions around coherent database operations.
  • Set timeouts for network calls.
  • Expose only the actuator endpoints that operators need.
  • Log enough context to trace a request without logging secrets.
  • Paginate collection endpoints and index common database lookups.

testing layers

TestWhat it protects
Unit testOne class or business rule in isolation.
Web slice testController serialization, validation, and HTTP behavior.
Repository testQueries and entity mappings against a database.
Integration testSeveral application layers working together.
End-to-end testA realistic client journey through the running system.

Use the official Spring Boot testing documentation as the detailed reference. Start with one test at the layer where a failure would be easiest to diagnose.

java -jar target/app.jar --server.port=8081

Spring Boot applications can run as executable JARs. The official build systems guide explains Maven and Gradle integration.

trade-offs to remember

  • JPA increases productivity but does not eliminate SQL knowledge.
  • Microservices increase independent deployment but add network and operational failure modes.
  • Eureka teaches discovery; it is not the only discovery mechanism used in production.
  • A gateway centralizes traffic policy; it should not become a second monolith.

Explain the request path from Postman to the database without looking at the code. Then identify where validation, business logic, persistence, discovery, load balancing, timeout handling, and observability happen.
