an HTTP request becomes useful when we give it a route, a contract, and a meaningful status code.

today's outcome

Build a first REST API and trace a request through Spring MVC: client → DispatcherServlet → controller → service → response.

create the project

Open Spring Initializr. Select Maven, Java, Java 17 or later, add Spring Web, generate the ZIP, extract it, and open the folder in IntelliJ. The official Building a RESTful Web Service guide follows the same path.

  1. Run the generated application.
  2. Confirm the embedded server starts on port 8080.
  3. Use Postman or a browser to call the first endpoint.

first controller

@RestController
@RequestMapping("/students")
public class StudentController {
    @GetMapping("/{id}")
    public StudentResponse getStudent(@PathVariable Long id) {
        return new StudentResponse(id, "Anurag", "anurag@example.com");
    }
}

public record StudentResponse(
    Long id,
    String name,
    String email
) {}

the endpoint vocabulary

AnnotationUse
@GetMappingRead a resource.
@PostMappingCreate a resource.
@PutMappingReplace a resource.
@PatchMappingPartially update a resource.
@DeleteMappingDelete a resource.
@RequestBodyRead JSON from the request body.
@RequestParamRead a query parameter such as ?branch=CSE.
@PathVariableRead a path value such as /students/12.

status codes are part of the API

  • 200 OK for a successful read or update.
  • 201 Created after creating a resource.
  • 204 No Content when success has no response body.
  • 400 Bad Request when the client sends invalid input.
  • 404 Not Found when the resource does not exist.
🧷 remember
A REST endpoint is a contract: method, URL, request shape, response shape, and status code.

practice

  1. Add list, create, update, and delete endpoints using an in-memory list.
  2. Test every endpoint in Postman and record request/response examples.
  3. Move the list operations into a separate @Service class.
