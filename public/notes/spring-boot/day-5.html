Spring Data JPA removes repetition, but it does not remove the database.

today's outcome

Replace the manual DAO with a Spring Data JPA repository and connect a REST API to a real database.

the complete application shape

Client
  ↓
Controller  — HTTP concerns
  ↓
Service     — business rules
  ↓
Repository  — persistence operations
  ↓
JPA → Hibernate → JDBC → Database

dependencies

Generate a project with Spring Web, Spring Data JPA, and your database driver. For local experiments, H2 is convenient; for realistic persistence, use MySQL or PostgreSQL and keep credentials in configuration.

Read the official Spring Data JPA reference for repository interfaces, query methods, and configuration.

the repository interface

public interface StudentRepository
        extends JpaRepository<Student, Long> {

    Optional<Student> findByEmail(String email);

    List<Student> findByNameContainingIgnoreCase(String name);
}

Spring creates the implementation at runtime. You declare the behavior; the framework supplies common persistence code.

service and controller

@Service
public class StudentService {
    private final StudentRepository repository;

    public StudentService(StudentRepository repository) {
        this.repository = repository;
    }

    public Student getRequired(Long id) {
        return repository.findById(id)
            .orElseThrow(() -> new StudentNotFoundException(id));
    }
}

@RestController
@RequestMapping("/students")
public class StudentController {
    private final StudentService service;

    @GetMapping("/{id}")
    public Student get(@PathVariable Long id) {
        return service.getRequired(id);
    }
}

entity is not automatically a DTO

Returning an entity directly can expose database structure, relationships, and fields that clients should not control. Prefer separate request and response objects:

public record StudentRequest(
    String name,
    String email,
    String branch
) {}

public record StudentResponse(
    Long id,
    String name,
    String email,
    String branch
) {}

pagination and sorting

Page<Student> page = repository.findAll(
    PageRequest.of(0, 20, Sort.by("name").ascending())
);

Never return an unbounded table to an API client. Pagination protects the database and gives clients predictable response sizes.

⚠️ gotcha
A repository method can look harmless while producing many queries. Learn to inspect SQL and watch for the N+1 problem when loading relationships.
