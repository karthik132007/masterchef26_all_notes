the single most famous question in software engineering interviews: "what happens when you type https://google.com into your browser and press Enter?"

the 30-second idea

A web request is not a single event — it is a choreographed symphony of electrical hardware interrupts, operating system kernel calls, cryptographic handshakes, fiber-optic transits, and distributed cloud computing spanning thousands of miles and completing in under 150 milliseconds.

Every single topic you have studied in this track — Ports, Sockets, DNS, Gateways, NAT, TCP, TLS, Proxies, and Connection Pools — functions as an interconnected cog in this grand machine. Below is the definitive, byte-level breakdown divided into 8 chronological phases.

⚡ The 8-Legged Transcontinental Relay Race
Typing a URL is like requesting an archived document from an underground vault across the ocean:
  • Leg 1 (The Dispatch Desk): You spell-check the name and check security clearances (URL parsing, HSTS).
  • Leg 2 (The Global Phonebook): You look up the vault's geographic coordinates (Iterative DNS resolution).
  • Leg 3 (The Driveway Ramp): Your vehicle gets an ignition key and checks the neighborhood map to find the exit gate (Socket syscall, routing table, ARP).
  • Leg 4 (The Highway Tollgate): Your car passes through the border checkpoint, swaps license plates, and roars onto transcontinental fiber highways (NAT/PAT and BGP Anycast).
  • Leg 5 (The Armored Convoy): You and the fortress guard exchange encrypted passcodes and rotating secret keys (TCP 3-way handshake and TLS 1.3 ECDHE).
  • Leg 6 (The Castle Moat & Gatekeeper): The guard verifies your credentials, inspects baggage for contraband, and unlocks the gate (Edge Reverse Proxy, TLS termination, WAF).
  • Leg 7 (The Treasury Archive): Internal staff borrows a warm mechanical cart to fetch the requested tome from distributed bookshelves (Internal gRPC, connection pool, distributed database).
  • Leg 8 (The Blueprint Painter): The pages arrive at your desk, and your team of artists drafts the blueprint, calculates box dimensions, and paints the pixels on canvas at 60 FPS (DOM, CSSOM, Render Tree, Layout Reflow, GPU composite).

the 8 phases in granular technical detail

PHASE 1

Browser Input Parsing & HSTS Preload

1. Hardware Interrupt: You hit Enter. The keyboard controller fires an electrical interrupt (IRQ 1) to the CPU. The OS keyboard driver forwards the keycode to the browser process.
2. URL Parsing: The browser parses scheme (https), host (google.com), and default port (443).
3. HSTS Preload Check: Chrome checks its hardcoded HTTP Strict Transport Security (HSTS) preload list. Because Google is on the list, the browser refuses to ever send unencrypted HTTP, automatically converting http:// to https:// internally before generating a single packet!

PHASE 2

Recursive DNS Resolution

1. Four-Tier Cache Check: Browser checks internal cache (chrome://net-internals/#dns) → OS cache (systemd-resolved / /etc/hosts).
2. Recursive Query: If missed, sends a UDP query on port 53 to the local gateway or public resolver (1.1.1.1 / 8.8.8.8).
3. Iterative Walk: The resolver walks the DNS hierarchy: Root Server (.) → TLD Server (.com) → Authoritative Server (ns1.google.com), returning the IPv4 A record: 142.250.190.46.

PHASE 3

OS Socket Allocation & ARP Next-Hop Routing

1. Socket Syscall: Browser invokes socket(AF_INET, SOCK_STREAM, 0). Kernel allocates a file descriptor and assigns an ephemeral port (e.g. 52140).
2. Subnet Route Evaluation: The kernel evaluates destination 142.250.190.46 against its local routing table. Because it is outside the local subnet (192.168.1.0/24), the next hop is designated as the Default Gateway (192.168.1.1).
3. ARP Resolution: The OS checks its local ARP cache table (arp -an). If missing, it broadcasts an ARP Request ("Who has 192.168.1.1? Tell 192.168.1.10") to get the Gateway's physical MAC address (Layer 2 frame header).

PHASE 4

Gateway Egress, PAT & BGP Internet Transit

1. Port Address Translation (PAT): The home router strips the private source IP (192.168.1.10:52140), substitutes its public WAN IP and an allocated external port (203.0.113.1:61022), logs the mapping in its state table, and recalculates checksums.
2. BGP Anycast Routing: The packet hops across Autonomous Systems (AS) via border gateway routers over transcontinental fiber cables, steered directly toward Google's nearest Anycast edge Point of Presence (PoP).

PHASE 5

TCP 3-Way Handshake & TLS 1.3 Encryption Tunnel

1. TCP 3-Way Handshake (1 RTT):
  • Client → SYN (seq = $X$)
  • Server → SYN-ACK (seq = $Y$, ack = $X+1$)
  • Client → ACK (ack = $Y+1$)
2. TLS 1.3 Key Exchange (1 RTT): Client sends ClientHello with SNI (google.com), ALPN (h2), and its ECDHE KeyShare. Server responds with ServerHello, its key share, and digital certificate. Both sides calculate the shared symmetric AES-256 secret. The encrypted channel is open in just 2 total RTTs!

PHASE 6

Edge Ingress, WAF & Layer 7 Reverse Proxy

1. Layer 4 Maglev Load Balancer: Hashes the 5-tuple and distributes the TCP stream across reverse proxy workers with zero packet copying.
2. Layer 7 Reverse Proxy (Envoy / Google Front End): Terminates the TLS connection, decodes the HTTP/2 frame, scans request headers for SQL injection or DDoS patterns via WAF, appends X-Forwarded-For, and checks the edge CDN cache.

PHASE 7

Microservice Execution & Database Querying

1. Internal Routing: The reverse proxy forwards the request over internal gRPC to the search cluster.
2. Connection Pool: An application worker thread borrows an existing warm socket from its database connection pool (zero TCP setup latency).
3. Business Logic & Query: The index search query runs across distributed storage (Spanner / Bigtable). The worker serializes HTML and HTTP response headers (200 OK, Content-Type: text/html, Set-Cookie), and streams chunks back down the TCP connection.

PHASE 8

Browser Critical Rendering Path & Pixel Rasterization

1. DOM Construction: As raw HTML bytes stream in, the browser's tokenizer converts bytes → characters → tokens → nodes into the DOM Tree.
2. CSSOM Construction: External stylesheets are fetched and parsed into the CSSOM Tree.
3. Render Tree: DOM and CSSOM combine into the Render Tree (omitting hidden nodes like <head> and display: none).
4. Layout (Reflow): Calculates exact geometry, bounding box coordinates, and sizes for every visible element on the viewport.
5. Paint & GPU Composite: Fills pixels (colors, fonts, borders, drop shadows) onto layers and composites them to the display screen at 60 FPS!

how to inspect each phase in your own terminal

# 1. Trace the DNS resolution hierarchy step-by-step
dig +trace google.com

# 2. Inspect your local Gateway IP and ARP hardware table
ip route show
ip neigh show

# 3. Trace every millisecond of the TCP, TLS, and TTFB lifecycle via curl
curl -vso /dev/null -w "\
DNS Lookup:        %{time_namelookup}s\n\
TCP Connect:       %{time_connect}s\n\
TLS Handshake:     %{time_appconnect}s\n\
Time to First Byte:%{time_starttransfer}s\n\
Total Duration:    %{time_total}s\n" https://www.google.com

# 4. Trace the router hops across the public internet to Google's Anycast edge
traceroute -T -p 443 google.com
