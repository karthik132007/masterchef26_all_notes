you type names, machines talk numbers — DNS translates.

the 30-second idea

DNS is the phonebook of the internet. You type www.manageengine.com, but machines only understand IPs like 165.173.187.32. DNS converts the name into the number — and the whole conversion in your image takes 6 steps and a fraction of a second.

  • The dumb-proof version: you want to call "Mom" but your phone needs her number. You (browser) ask your assistant (resolver), who checks the directory (root), then the area office (TLD), then her own contact card (authoritative) — and dials.
  • One rule for the whole page: green arrows ask, blue arrows answer. The resolver does all the walking. You just wait.
🧷 remember
DNS turns names into IPs. Your browser never hunts — it asks one helper, the DNS resolver, and the resolver runs the full chain for it.

meet everyone first

Four characters. Learn who knows what — nobody knows everything:

  • DNS resolver — your assistant. Usually run by your ISP or set to someone like Google (8.8.8.8). Takes your question and chases the answer across the internet.
  • Root server — the top directory. Doesn't know any website's IP. Only knows one thing: who handles each ending like .com.
  • TLD server — the area office for one ending (.com). Doesn't know the IP either. Only knows who owns each name under it, like manageengine.
  • Authoritative DNS — the owner's own card. The only one that knows the real IP: www.manageengine.com = 165.173.187.32.

one name's full journey — follow the numbers

the trip, step by step

  • 1 — You type the name. www.manageengine.com goes into the browser. The browser has no idea what IP that is.
  • 2 — Browser asks the resolver. One question, upward: "what IP is www.manageengine.com?" The browser's job ends here — it just waits.
  • 3 — Resolver asks the root. The root doesn't know the IP. It answers with a referral: the nameservers of the .com TLD — "not my department, try them."
  • 4 — Resolver asks the TLD. The .com server doesn't know the IP either. It answers with another referral: the nameservers of manageengine.
  • 5 — Resolver asks the authoritative DNS. This one actually owns the answer and replies with the real thing: 165.173.187.32.
  • 6 — Resolver hands you the IP. The browser finally gets 165.173.187.32 and loads the page.
⭐ exam tip
Full-marks order: browser → resolver → root → TLD → authoritative → back to browser. And the punchline: only the authoritative server gives the IP — root and TLD only give referrals.

why the chain — why not ask the owner directly?

Because the resolver doesn't know who the owner is. The internet has millions of names; no single server lists them all. So each level answers the only question it can:

  • Root: "I don't know manageengine.com. But .com lives over there."
  • TLD: "I don't know the IP. But manageengine's nameservers are over there."
  • Authoritative: "That's mine. 165.173.187.32."

Like asking for a person: directory → area office → their own desk. Three referrals, one answer.

⚠️ gotcha
The root never gives you an IP. If an option says "root server returns 165.173.187.32", it is wrong — root only points to the TLD. Also: the resolver remembers answers until their timer (TTL) runs out, which is why the second visit to a site feels instant.

quick check

  • Who does the browser ever talk to? Only the resolver. It asks once (step 2) and receives once (step 6).
  • The TLD says "I don't know". Is something broken? No — that is its job. It replies with a referral to the owner's nameservers.
  • Which box would you raid to change manageengine.com's IP? The authoritative DNS. It is the single source of truth; everywhere else just points toward it.
