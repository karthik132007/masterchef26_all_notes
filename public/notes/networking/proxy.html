a proxy is an intermediary that speaks on someone else's behalf. But who is it protecting: the client who asks, or the server that answers?

the 30-second idea

A Forward Proxy protects and represents the client. A Reverse Proxy protects and represents the web server.

🕶️ The Secret Agent vs The Celebrity Bodyguard

  • Forward Proxy (The Secret Agent): You want to buy sensitive documents from an arms dealer without revealing your identity. You hire a secret agent (Forward Proxy) to do the transaction. The seller only sees the agent's trenchcoat and briefcase; they have zero idea you exist.
  • Reverse Proxy (The Celebrity Bouncer & Receptionist): A movie star lives in a secure compound with 20 chefs and assistants. Fans knock on the front gate. The bouncer (Reverse Proxy) checks their ID, inspects their bags, terminates security threats, and hands them an autographed photo from the gift shop. Fans never enter the house or see the private staff.
🧷 remember
Forward Proxy = Hides clients from the internet. (Client configures it; Server is oblivious).
Reverse Proxy = Hides servers from the internet. (Client is oblivious; Server sits safely behind it).

the proxy headers: preserving real client identity

When a reverse proxy forwards an HTTP request, the backend application sees the proxy's private IP as the remote address. The proxy appends forwarding headers to preserve reality:

GET /v1/checkout HTTP/1.1
Host: shop.com
X-Forwarded-For: 203.0.113.195, 10.0.0.1
X-Forwarded-Proto: https
X-Forwarded-Port: 443
Forwarded: for=203.0.113.195;proto=https;by=203.0.113.1
⚠️ the x-forwarded-for spoofing vulnerability
Never blindly trust request.headers["x-forwarded-for"] for rate limiting or security access control! A malicious client can send X-Forwarded-For: 127.0.0.1 in their initial request. If your proxy appends to it, the backend might believe the request originated from localhost! Only trust the leftmost IP if your reverse proxy is configured to strip incoming untrusted client headers.
