the 30-second idea

A load balancer sits in front of your servers and splits incoming requests across them, so no single server melts while the others sit idle.

  • Without one: 10,000 users hit a single server. It slows, then dies, then everyone sees an error page.
  • With one: the same 10,000 users are shared across Server 1, 2 and 3. One server can die and nobody notices.
  • Four things you get for free: high availability, scalability, better performance, fault tolerance.

L4 vs L7 — the only comparison that matters

L4 is fast and dumb. L7 is smart and a little slower. That is the whole fight.

  • L4 is a postman. He never reads your letter — he checks the PIN code and house number and moves on. That is routing on IP + port.
  • L7 is hospital reception. It asks what is wrong first — fever to Room 1, fracture to Room 2. That is routing on content like URL, headers and cookies.

the 6 algorithms

Each one answers a different question. Read the question first, the name second.

1. Random — just roll the dice

No memory, no order. Every request lands on any server. Fine when all servers are identical and you want the simplest thing possible.

2. Round robin — roll numbers in class

Go in a circle: S1 → S2 → S3 → S1 → S2 → S3… Everyone gets exactly one turn, fairly. Best when all servers are equally powerful.

3. Weighted round robin — the strong server lifts more

Strong servers get more turns. With weights 5-3-2, out of 10 requests S1 takes 5, S2 takes 3, S3 takes 2. Use it when your servers have different sizes.

4. Least connections — join the shortest queue

Every new request goes to whoever is least busy right now. If S1 holds 10 connections, S2 holds 5 and S3 holds 2, the next request goes to S3. A live score, not a fixed ratio — best when requests take uneven time.

5. Path based — the URL decides

Route by URL path: /api → S1, /images → S2, /files → S3. Only an L7 balancer can do this, because L4 cannot even read URLs. The classic microservices pick.

6. IP hash — the same customer keeps their barber

hash(client IP) pins each user to one server, every visit. Client A always lands on S1, B on S2, C on S3. Logins and carts survive. That stickiness is called session persistence.

⚠️ gotcha
Weighted is a fixed power ratio set once by you. Least-connections is live busyness measured every second. Path-based needs L7. IP hash is the only one that remembers the client.

quick check

  • A video site serves a million viewers — L4 or L7? L4. You need raw throughput for streams; nobody needs to read URLs.
  • /pay needs secure servers, /blog needs cheap ones? Path based, on an L7 balancer — only L7 can split by URL path.
  • Users keep getting logged out mid-session? IP hash. It pins each client to one server, so the session stays alive.

the 20-second answer

A load balancer splits client requests across servers for availability and scale. L4 routes on IP and port, so it is very fast. L7 routes on content such as URLs and cookies, so it is smarter. Round-robin suits equal servers, weighted suits unequal ones, least-connections suits uneven work, path-based suits microservices, and IP hash suits sticky sessions.
