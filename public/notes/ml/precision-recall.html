accuracy lies when disease is rare. meet the two numbers that don't — plus the one that marries them.

the 30-second idea

Pages 20–21 use a disease test: 99 healthy, 1 sick. A lazy model saying "healthy" always scores 99% accuracy — and kills the patient. So your notes split every prediction into four boxes, then build precision ("when I shout, am I right?") and recall ("of all sick, how many did I catch?"). Neither alone is honest; F1 forces both to be good.

precision vs recall — row vs column (the only way to remember)

$$\text{Precision}=\frac{TP}{TP+FP}\;(\text{row: of my alarms, how many real}),\quad \text{Recall}=\frac{TP}{TP+FN}\;(\text{col: of sick, how many caught})$$ $$\text{Accuracy}=\frac{TP+TN}{TP+FP+FN+TN}\quad\text{(lies when skewed)}$$
  • High precision, low recall — silent sniper: rarely shouts, always right. Misses victims. Spam filter that hides real mail = angry users. Disease test that misses sick = dead patients.
  • Low precision, high recall — paranoid guard: catches everyone, cries wolf daily. Hospital panics 100 healthy per 1 sick — exhausting and expensive.

F1: the strict parent (harmonic mean)

Your notes ask: 3 algos, different P and R — who wins? Simple average lies (0.9+0.1→"0.5 fine!"). F1 is harmonic mean — it punishes lopsidedness:

$$F_{1}=\frac{2PR}{P+R}\qquad \frac{1}{F_{1}}=\tfrac12\!\left(\tfrac1P+\tfrac1R\right)\;\;\text{(harmonic mean)}$$
algoPRF1verdict
algo 10.50.9~0.64balanced-ish ★ winner
algo 20.70.1~0.18recall collapsed ☠️
algo 30.90.2~0.33precise but blind

Straight from your page 21: algo 1 wins on F1 even though algo 3 has shiniest precision. F1 drags show-offs back to earth. If you care more about recall (disease) you can weight it → Fβ, but F1 is default.

threshold trade-off — moving the 0.5 line

Logistic/SVM give scores/probabilities; threshold \tau turns them into labels ($\ge \tau \to 1$). Sliding \tau traces the Precision-Recall curve:

\tau high (e.g. 0.8)

Only very confident → precision ↑, recall ↓. Few alarms, mostly correct, many missed.

\tau low (e.g. 0.2)

Even unsure → alarm → recall ↑, precision ↓. Catches everyone, many false alarms.

Pick \tau on validation to maximize F1 (or business cost). That is why your notes' 3-algo table is really a 3-threshold story.

python from scratch — no sklearn.metrics needed

● ● ●python — confusion + P/R/F1 from scratch
import numpy as np

def confusion_matrix(y_true, y_pred):
    # y_true, y_pred ∈ {0,1}
    TP = np.sum((y_true==1) & (y_pred==1))
    TN = np.sum((y_true==0) & (y_pred==0))
    FP = np.sum((y_true==0) & (y_pred==1))
    FN = np.sum((y_true==1) & (y_pred==0))
    return np.array([[TP, FP],[FN, TN]])  # [[TP,FP],[FN,TN]] as in notes

def precision_recall_f1(y_true, y_pred):
    TP = np.sum((y_true==1) & (y_pred==1))
    FP = np.sum((y_true==0) & (y_pred==1))
    FN = np.sum((y_true==1) & (y_pred==0))
    prec = TP / (TP+FP) if (TP+FP)>0 else 0.0
    rec  = TP / (TP+FN) if (TP+FN)>0 else 0.0
    f1   = 2*prec*rec/(prec+rec) if (prec+rec)>0 else 0.0
    return prec, rec, f1

# ── skewed disease example: 99 healthy, 1 sick
y_true = np.array([1] + [0]*99)   # 1 sick, 99 healthy
y_lazy = np.zeros(100, dtype=int)            # "always healthy" model

print("lazy accuracy", np.mean(y_lazy==y_true))          # 0.99 — looks genius
print(precision_recall_f1(y_true, y_lazy))               # (0.0, 0.0, 0.0) — actual failure

# ── 3-algo showdown from your notes page 21
for p,r in [(0.5,0.9),(0.7,0.1),(0.9,0.2)]:
    f1 = 2*p*r/(p+r)
    print(f"P={p} R={r} → F1={f1:.3f}")
# P=0.5 R=0.9 → F1=0.643 ★ winner (balanced)
● ● ●python — sweep threshold → best F1
# logistic scores → pick \tau that maximizes F1
y_true = np.array([1,0,1,1,0,0,1,0])
scores = np.array([0.92,0.45,0.60,0.81,0.30,0.55,0.70,0.10])

best_f1, best_t = 0, 0.5
for t in np.linspace(0.1,0.9,9):
    pred = (scores >= t).astype(int)
    _,_,f1 = precision_recall_f1(y_true, pred)
    print(f"\tau={t:.1f} → F1={f1:.3f}")
    if f1 > best_f1: best_f1, best_t = f1, t
print(f"★ best \tau={best_t:.2f} (F1={best_f1:.3f})")

Write both formulas + the table verdict: P=TP/(TP+FP), R=TP/(TP+FN), F1=2PR/(P+R), and "algo 1 wins (F1≈0.64)". Examiners reuse this exact 3-algo comparison. Add one line: "accuracy fails on skewed data — always quote P/R/F1."
🔬 try it: feel F1's strictness

P=1.0, R=0.1 → plain average = 0.55 ("passing!"). F1 = 2·1·0.1/1.1 ≈ 0.18 ("failing"). F1 sides with the weaker twin — both must be decent to score well. That's why it's harmonic, not arithmetic.

print(2*1.0*0.1/(1.0+0.1))  # 0.181
print((1.0+0.1)/2)           # 0.55  arithmetic — lies!
⚠️ gotcha
Accuracy on skewed data is a scam. 99-to-1 disease data + "always healthy" = 99% accuracy, 0 recall, dead patients. Also: P/R/F1 are defined for the POSITIVE class — swap what you call positive and numbers flip. Always state $positive = disease/spam = 1$.

quick check

  • FP vs FN — which kills in disease screening? FN (missed sick). Recall is life-saver there → you'd lower \tau.
  • Perfect model — P,R,F1? All 1.0. Only TP+TN, no FP/FN.
  • Why harmonic not plain mean? Plain mean rewards "great at one, awful at other". Harmonic demands both.
  • When to weight recall over precision? Disease, fraud, safety — where missing a positive is catastrophic.

the 20-second answer

Confusion matrix splits into TP/FP/FN/TN. Precision = TP/(TP+FP) (alarm quality), Recall = TP/(TP+FN) (catch rate), F1 = 2PR/(P+R) picks the balanced winner — your notes crown algo 1 (~0.64).
