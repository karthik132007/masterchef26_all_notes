no labels? no problem. let the dots form their own gangs — the only unsupervised crowd-splitter you need first.

the 30-second idea

Pages 27–30 return to unsupervised learning: clustering = gang up similar dots. Your notes' height+weight example → short-light, tall-heavy, middle crowd. Rule: inside a cluster = close; across clusters = far. K-means is the simplest gang-maker: pick K, alternate assign → move centroids till nobody moves. The cost J is the average squared walk to your gang's star ★.

K-means in 5 steps (your pages 28–30, unchanged but explained)

1. choose K            e.g. K=3 → want 3 gangs (you pick K, algorithm never learns it)
2. init centroids      random dots as μ₁,μ₂,μ₃ (or random points in range)
3. ASSIGN              each dot → nearest centroid (Euclidean distance usually)
4. MOVE                centroid = mean of its gang  →  μk = (Σ x⁽ⁱ⁾ in k)/count_k
5. repeat 3–4 till centroids barely move (Δ < ε) or max_iters

the cost J: how bad is the gang-map?

$$J(c^{(1)}\!\dots\!c^{(m)},\mu_{1}\!\dots\!\mu_{K})=\frac{1}{m}\sum_{i=1}^{m}\left\|x^{(i)}-\mu_{c^{(i)}}\right\|^{2}$$
$c^{(i)}$ = cluster of point $i$, $\mu_{k}$ = centroid $k$

Translation: average squared walk from each dot to its gang's star. Tight gangs = small J. Both steps (assign, move) provably never increase J — so the loop must converge (to a local optimum, not necessarily global — keep that distinction).

● ● ●python — KMeans from scratch
import numpy as np
import matplotlib.pyplot as plt

class KMeans:
    def __init__(self, K=3):
        self.k = K
        self.centroids = None

    @staticmethod
    def euclidean_distance(data_point, centroids):
        # data_point: (n,)  centroids: (K,n) → distances (K,)
        return np.sqrt(np.sum((centroids - data_point)**2, axis=1))

    def fit(self, X, max_iters=100):
        # 1. random init inside data range
        low, high = np.amin(X, axis=0), np.amax(X, axis=0)
        self.centroids = np.random.uniform(low, high, size=(self.k, X.shape[1]))

        for it in range(max_iters):
            # 2. ASSIGN — nearest star wins
            labels = []
            for pt in X:
                dists = KMeans.euclidean_distance(pt, self.centroids)
                labels.append(np.argmin(dists))
            y = np.array(labels)

            # 3. MOVE — mean of each gang
            new_centroids = []
            for k in range(self.k):
                members = X[y==k]
                if len(members)==0:          # empty cluster → keep old star
                    new_centroids.append(self.centroids[k])
                else:
                    new_centroids.append(members.mean(axis=0))
            new_centroids = np.array(new_centroids)

            # 4. check convergence (max move < 1e-4)
            if np.max(np.abs(self.centroids - new_centroids)) < 1e-4:
                print(f"converged at iter {it}"); self.centroids = new_centroids; break
            self.centroids = new_centroids

        return y   # labels for each point

# ── demo: 100 random points, K=3
np.random.seed(0)
X = np.random.randint(0, 100, size=(100,2))
model = KMeans(K=3)
labels = model.fit(X, max_iters=100)

plt.scatter(X[:,0], X[:,1], c=labels, s=40, cmap='tab10', edgecolors='#1c1a15')
plt.scatter(model.centroids[:,0], model.centroids[:,1], marker='*', s=350, c='#ffe14d', edgecolors='#1c1a15', linewidth=2)
plt.title("KMeans from scratch — ★ = centroids"); plt.show()
● ● ●python — compute J + elbow to pick K
def compute_cost(X, labels, centroids):
    m = X.shape[0]; cost=0.0
    for i in range(m):
        cost += np.sum((X[i]-centroids[labels[i]])**2)
    return cost/m

Ks = range(1,8); Js=[]
for k in Ks:
    mdl=KMeans(K=k); labs=mdl.fit(X, max_iters=100)
    Js.append(compute_cost(X, labs, mdl.centroids))

plt.plot(list(Ks), Js, marker='o', linewidth=2.5, color='#1c1a15')
plt.xlabel("K"); plt.ylabel("J (mean squared distance)"); plt.title("elbow: K where J stops dropping fast → pick it")
plt.grid(True, alpha=0.3); plt.show()

practical knobs & gotchas

  • Scale features! K-means uses Euclidean distance — if one feature is 0–10000 and another 0–1, the big one dominates. Always standardize → then cluster.
  • K-means++ init: spread initial stars far apart → faster + better minima (sklearn default). Our random uniform is didactic; mention k-means++ in viva.
  • Local optima: random start → random finish. Run 5–10 times with different seeds, keep lowest J.
  • J=0? → K=m (every dot its own gang) — memorised, useless. Like overfit.
⚠️ gotcha
K is not learned — you pick it. Elbow is heuristic, not a theorem. The algorithm never tells you the "right" K; domain knowledge + validation does. Also: K-means loves spherical, equal-size gangs; moons / rings will be butchered — use DBSCAN or spectral clustering there.

quick check

  • K=3 means? Three clusters, three centroids μ₁,μ₂,μ₃.
  • Assign uses what? Distance (usually Euclidean) dot → each star, take min.
  • Why K-means++? Smarter init → less chance of terrible local minima.

the 20-second answer

K-means: pick K, scatter stars, assign dots to nearest star, move stars to gang means, repeat. Cost is mean squared dot→star distance; loop shrinks it till stars freeze (local optimum). Run many starts, pick lowest J, choose K by elbow/domain. Last unsupervised trick: lonely weirdos → Anomaly Detection.
