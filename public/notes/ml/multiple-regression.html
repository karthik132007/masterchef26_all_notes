one feature was a toy — real houses have size, beds, age, zip. meet vectors: same line, n dimensions.

the 30-second idea

Pages 10–12: stop writing w₁x₁ + w₂x₂ + … forever. Pack weights into a vector w, features into x, and the model collapses to $f = w\cdot x + b$ (dot product + bias). Same line idea, now in n-dimensions — a plane (n=2), then a hyperplane you cannot draw but can compute. Gradient descent scales the same.

$$f_{w,b}(x)=w_{1}x_{1}+w_{2}x_{2}+\cdots+w_{n}x_{n}+b = w^{\top}x + b$$
$$w=[w_{1}\;\dots\;w_{n}],\quad x=[x_{1}\;\dots\;x_{n}],\quad X\in\mathbb{R}^{m\times n}$$

why vectors matter — beyond neat writing

Three reasons your notes hammer vectorization:

  • Math compression: n separate update rules → one vector rule $w := w - \alpha\cdot \nabla_w J$.
  • Speed: np.dot(w, x) hands the whole operation to optimized C/BLAS, not a Python loop. 1M features → milliseconds vs seconds.
  • Geometry: Cost bowl now lives in (n+1)-D — still convex, still one bottom.

vectorization: slow loop vs one BLAS punch

● ● ●python — loop vs vectorized prediction
import numpy as np

w = np.array([2.0, -1.0, 0.5])
x = np.array([3.0, 4.0, 10.0])
b = 1.0

# 🐢 loop (n steps in Python — what naive code does)
f_loop = 0.0
for j in range(len(w)):
    f_loop += w[j] * x[j]
f_loop += b                     # → 8.0

# 🐇 vectorized (one BLAS call — what you should write)
f_vec = np.dot(w, x) + b       # → 8.0  — same answer, 100× faster at scale
# also: f_vec = w @ x + b

print(f_loop, f_vec)

vectorized cost and gradient — the money equations

Page 12 compresses all n gradient updates into two matrix punches. Learn this table by heart:

quantityformulashape
prediction$\hat{y} = X\cdot w + b$m × 1
cost$J = 1/(2m)\cdot \sum(\hat{y}-y)^{2} = 1/(2m)\cdot ||\hat{y}-y||^{2}$scalar
errore = ŷ − ym × 1

● ● ●python — vectorized cost + gradient (from scratch)
def cost_vectorized(X, y, w, b):
    m = X.shape[0]
    y_hat = X.dot(w) + b
    return (1/(2*m)) * np.sum((y_hat - y)**2)

def compute_gradient_vec(X, y, w, b):
    m = X.shape[0]
    y_hat = X.dot(w) + b
    error = y_hat - y                 # m-vector
    dj_dw = (1/m) * (X.T.dot(error))    # n-vector ★ Xᵀ·error
    dj_db = (1/m) * np.sum(error)        # scalar
    return dj_dw, dj_db

# gradient descent — now with vectors
def gradient_descent_vec(X, y, w_init, b_init, alpha, num_iters):
    w, b = w_init.copy(), b_init
    for i in range(num_iters):
        dj_dw, dj_db = compute_gradient_vec(X, y, w, b)
        w -= alpha * dj_dw
        b -= alpha * dj_db
    return w, b

feature scaling — the hidden trap

When one feature is 0–1 (bedrooms) and another is 1000–5000 (sqft), the cost bowl becomes a stretched elliptical valley — gradient descent zig-zags and crawls. Fixes:

techniqueformulawhen
Standardize (z-score)$(x - \mu)/\sigma$ → mean 0, std 1default for GD ★
Min-max(x − min)/(max−min) → [0,1]when you need bounded
Mean-normalize$(x - \mu)/(max-min)$variant of above
● ● ●python — standardize features (must-do before GD)
X_raw = np.array([[2100, 3],
                [1600, 2],
                [2400, 4],
                [1400, 2]])
mu = X_raw.mean(axis=0)          # [1875, 2.75]
sigma = X_raw.std(axis=0)         # std per column
X_norm = (X_raw - mu) / sigma     # now both cols ~ N(0,1) → round bowl → GD flies

# remember mu/sigma and apply same transform to test houses!
⚠️ gotcha
Xᵀ not X. X is m×n; error is m×1. Only X-transpose (n×m) times error gives the n×1 gradient you need. Wrong order = shape explosion. Also: scale train and test with same μ,σ from train only — don't recompute on test.

quick check

  • 4 features — how many w's? 4 (w₁…w₄) + one b. Always n weights, one bias.
  • Vectorized f for one example? $w\cdot x + b$. For all m? $X\cdot w + b$.
  • Gradient shape? Same shape as w — one slope per knob.
  • Why standardize? → Makes bowl round, GD converges 10–100× faster.

the 20-second answer

Multiple regression is f = w·x + b: stack features into vectors, dot them, add bias. Vectorization swaps n Python loops for one BLAS dot product, and the gradient becomes Xᵀ·error / m.
