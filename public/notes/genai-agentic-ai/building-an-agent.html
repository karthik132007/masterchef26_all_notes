the 30-second idea

In Topic 09, we learned the theory of agents: Brain + Tools + Loop. But if you code an agent from scratch with raw OpenAI APIs, you have to write ~80 lines of manual JSON schemas, parse tool_calls dictionaries, manually match function names, run exceptions catchers, and append messages back to the context.

LangChain turns all of that boilerplate into 5 readable lines of Python.

You write regular Python functions for what you want the agent to do (like checking the weather or reading today's calendar), mark them with the @tool decorator, and LangChain handles everything else: schema generation, tool execution, and the reasoning loop.

🧠 1. The Brain (Chat Model)

A tool-aware LLM (such as gpt-4o-mini) that decides which tool to call based on the user's question, or answers immediately if no tool is required.

🛠️ 2. The Tools (Hands)

Ordinary Python functions decorated with @tool. For our beginner agent, we'll build two essential tools: get_weather and get_current_date.

🔄 3. The Agent Loop (Nervous System)

Built with create_react_agent. It runs the ReAct cycle (Reason → Act → Observe) automatically until the task is complete.

🧷 the beginner mental model
LLMs have no internal wristwatch and no real-time internet senses. Their training weights are frozen in time. Giving an agent get_current_date gives it a watch; giving it get_weather gives it a window outside.

why langchain? (from scratch vs framework)

Why do developers use LangChain rather than writing raw API loops? Let's compare them side-by-side:

Dimension Building from Scratch (Raw API) Building in LangChain
Tool Definition Requires typing 20+ lines of nested JSON Schema dictionaries (type: "object", properties: {...}) for every single function. Write a regular Python function and slap @tool on top. LangChain auto-generates the JSON schema from your type hints and docstring.
Tool Execution Write custom if/elif blocks or a dictionary registry (TOOL_MAP[call.name](**args)) with manual json.loads. 100% automated: LangChain inspects the LLM's requested tool call, executes the Python function, and packages the output into a ToolMessage.
Agent Loop & State Write manual while loops, step counters, and manage message array mutation manually. One line: create_react_agent(model, tools). Supports parallel tool calls and error recovery out-of-the-box.
Model Portability Rewriting payload formats if switching from OpenAI to Anthropic Claude, Google Gemini, or local Ollama. Zero code changes in your tools. Just swap ChatOpenAI with ChatAnthropic or ChatGoogleGenerativeAI.

architecture: how our weather & date agent works

Here is the entire lifecycle of a user request through our LangChain agent:

step 1: environment & installation

To build modern LangChain agents, you only need three core packages:

pip install langchain langchain-openai langgraph

Set your OpenAI API key in your terminal or inside your Python file:

import os

step 2: creating custom tools with @tool

In LangChain, a tool is just a standard Python function that has the @tool decorator on top of it. LangChain automatically inspects two things in your function:

  1. Type Annotations: Tells the LLM what data types each parameter takes (e.g. city: str).
  2. The Docstring ("""..."""): This is prompt engineering for tools! The LLM reads your docstring to understand what the tool does and when to invoke it.

tool 1: getting the current date and time

Because LLMs have a fixed knowledge cutoff date, they don't know what day today is. We provide a simple function using Python's built-in datetime module:

import datetime
from langchain_core.tools import tool

@tool
def get_current_date() -> str:
    """Returns the current date, day of the week, and time.
    Use this tool whenever the user asks for today's date, current day, or current time.
    """
    now = datetime.datetime.now()
    return now.strftime("%A, %B %d, %Y (%I:%M %p)")

tool 2: getting current weather

Next, we build a weather tool. In a beginner project, we can use a dictionary of major cities (or connect to a free weather API like OpenWeatherMap in production):

@tool
def get_weather(city: str) -> str:
    """Get the current weather forecast and temperature for a given city.
    
    Args:
        city: The name of the city (e.g. 'Tokyo', 'London', 'New York').
    """
    # Sample mock database for beginner testing
    weather_db = {
        "tokyo": "Sunny, 18°C (64°F), Wind: 8 km/h, Humidity: 45%",
        "london": "Light rain & overcast, 12°C (54°F), Wind: 15 km/h, Humidity: 85%",
        "new york": "Partly cloudy, 15°C (59°F), Wind: 12 km/h, Humidity: 60%",
        "paris": "Mild and breezy, 16°C (61°F), Wind: 10 km/h, Humidity: 50%",
        "bengaluru": "Pleasant, 24°C (75°F), Wind: 6 km/h, Humidity: 55%"
    }
    
    city_key = city.lower().strip()
    if city_key in weather_db:
        return f"Current weather in {city.title()}: {weather_db[city_key]}"
    
    # Sensible fallback for unlisted cities
    return f"Current weather in {city.title()}: Partly cloudy, 20°C (68°F), Humidity: 52%"
🧷 golden rule: never skip the docstring
If you write a function with no docstring, the LLM receives an empty description. It will literally guess blindly about what the tool does! Always write a clear, descriptive docstring explaining what the tool does and what arguments it expects.

step 3: assembling the complete agent

Here is the complete, self-contained Python script. Notice how few lines of code are required!

# weather_date_agent.py
import datetime
import os
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent

# 1. Ensure API key is configured
# os.environ["OPENAI_API_KEY"] = "sk-..."

# 2. Define our custom tools
@tool
def get_current_date() -> str:
    """Returns today's current date, day, and time."""
    return datetime.datetime.now().strftime("%A, %B %d, %Y")

@tool
def get_weather(city: str) -> str:
    """Get current weather forecast for a given city."""
    weather_db = {
        "tokyo": "Sunny, 18°C, Humidity 45%",
        "london": "Light rain, 12°C, Humidity 85%",
        "new york": "Partly cloudy, 15°C, Humidity 60%",
        "paris": "Mild, 16°C, Humidity 50%",
        "bengaluru": "Pleasant, 24°C, Humidity 55%"
    }
    return weather_db.get(city.lower().strip(), f"Partly cloudy, 20°C in {city}")

# 3. Combine tools into a list
tools = [get_current_date, get_weather]

# 4. Initialize the Brain (temperature=0 ensures accurate tool selection)
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# 5. Build the ReAct Agent in one line
agent = create_react_agent(model, tools)

# 6. Run the agent with a question needing BOTH tools!
user_query = "What is today's date, and what's the weather like in Tokyo right now?"
print(f"User: {user_query}\n")

# Run the agent!
result = agent.invoke({
    "messages": [{"role": "user", "content": user_query}]
})

# The final message in the array is the assistant's final synthesized answer
final_answer = result["messages"][-1].content
print(f"Agent:\n{final_answer}")

under the hood: step-by-step trace walkthrough

What actually happened inside when we invoked agent.invoke()? LangChain managed a 4-step conversation for us:

Step Message Type Sender What Happened?
1 HumanMessage User "What is today's date, and what's the weather like in Tokyo right now?"
2 AIMessage (with tool calls) GPT-4o-mini The model determines it doesn't know the date or current Tokyo weather. Instead of hallucinating, it requests two tool calls in parallel:
  • call_1: get_current_date()
  • call_2: get_weather(city="Tokyo")
3 ToolMessage (x2) LangChain Runtime LangChain runs your Python functions locally and sends the outputs back to the model:
  • Result 1: "Wednesday, September 30, 2026"
  • Result 2: "Sunny, 18°C, Humidity 45%"
4 AIMessage (Final Answer) GPT-4o-mini The model now has all required facts. It synthesizes a natural English answer: "Today is Wednesday, September 30, 2026. The weather in Tokyo is currently sunny at 18°C with 45% humidity."

You can print all messages in the trace by iterating through the state:

for msg in result["messages"]:
    print(f"[{msg.__class__.__name__}]: {msg.content or msg.tool_calls}")

legacy vs modern langchain (don't get tripped up online)

If you search for LangChain tutorials online, you will encounter older code written in 2023 that is now deprecated. Here is how to recognize the old way versus the modern standard:

❌ The Old Way (Deprecated 2023)

initialize_agent(tools, llm, agent=AgentType.ZERO_SHOT_REACT_DESCRIPTION)

Relied on fragile text regex parsing (extracting Action: ... and Action Input: ... from raw token streams). It broke often when models formatted text slightly differently.

✅ The Modern Way (2025/2026 Standard)

from langgraph.prebuilt import create_react_agent

Uses native model function calling (OpenAI tool calling API). Fully typed, supports parallel tool calls, built-in state graphs, and clean tracing.

beginner gotchas & best practices

⚠️ top 4 beginner mistakes in langchain agents
  • 1. Forgetting Type Hints: If you write def get_weather(city): without city: str, LangChain cannot generate the parameter JSON schema, and the LLM may pass integers or null values.
  • 2. Vague or Missing Docstrings: Writing """weather tool""" provides no instructions. Always specify what inputs the tool expects and what information it returns.
  • 3. Setting High Temperature: Always set temperature=0 when creating an agent. High temperatures (e.g. 0.9) increase creativity, which causes the LLM to hallucinate invalid tool names or parameters!
  • 4. Crashing Inside the Tool Function: If your tool raises an unhandled Python exception, your entire app terminates. Always return a friendly error string (e.g. return f"City '{city}' not found in database.") so the agent can self-correct!

interview drill & architecture checklist

⭐ top 5 agent interview questions
  1. Q: How does LangChain's @tool decorator convert a Python function into an LLM tool?
    Answer: LangChain uses Python's inspect and pydantic to extract the function name, the docstring (used as the tool description), and the type annotations (used to construct the JSON Schema parameter specification).
  2. Q: Can an agent invoke multiple tools at the same time?
    Answer: Yes! Modern chat models support parallel tool calling. When asked for both today's date and Tokyo weather, GPT-4o emits two tool calls in a single turn. LangChain executes both and feeds both observations back to the LLM.
  3. Q: How does the agent know when to stop calling tools?
    Answer: When the model inspects its context and decides it has enough information to satisfy the user request, it outputs standard text content without requesting any new tool_calls. LangChain detects this and terminates the loop.
  4. Q: What is the purpose of setting temperature=0 in agent applications?
    Answer: Zero temperature makes token sampling greedy and deterministic. This minimizes hallucinations, guarantees consistent schema adhering, and ensures the model picks the exact matching tool name.
  5. Q: Why is LangGraph preferred over legacy AgentExecutor?
    Answer: LangGraph models agent loops as cyclic directed graphs (DAGs). This provides first-class support for persistence, streaming intermediate steps, human-in-the-loop approvals, and multi-agent coordination without monolithic abstractions.
