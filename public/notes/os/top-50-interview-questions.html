1. processes, threads & concurrency (q1 – q10)

Q01
OpenAI Meta Processes & Threads
What is the exact distinction between a process and a thread inside the Linux kernel? How does clone() implement both?
Show Answer ▾
Direct Takeaway To the Linux kernel scheduler, there is no fundamental difference: both processes and threads are represented by the exact same C struct: struct task_struct. The difference is solely what resources are shared, controlled by flags passed to the clone() syscall.

In Linux, every schedulable unit is a task (often called a lightweight process). When you invoke fork(), it calls clone() with Copy-On-Write memory. When you create a POSIX thread with pthread_create(), it invokes clone() with specific resource-sharing flags:

  • CLONE_VM: The new task shares the exact same virtual memory address space (same page tables, mm_struct).
  • CLONE_FS: Shares filesystem information (root directory, cwd, umask).
  • CLONE_FILES: Shares the open file descriptor table (writing to fd 3 in thread A is instantly visible to thread B).
  • CLONE_SIGHAND: Shares signal handlers.
  • CLONE_THREAD: Placed into the same thread group (shares the same process ID PID returned by getpid(), but has a unique thread ID TID).
⚠️ Interview Trap: Candidates often say "threads share the stack." While threads have their own separate stack pointer (RSP) and dedicated stack memory region, there is no hardware memory protection between them. A pointer in Thread A can corrupt Thread B's stack if they share the same address space.
Q02
Anthropic Google Context Switching
What happens step-by-step during a CPU context switch, and why does a thread switch have lower latency than a process switch?
Show Answer ▾
Direct Takeaway A context switch saves the architectural state of the outgoing task and loads the state of the incoming task. Switching between threads of the same process preserves the page table (CR3 register), avoiding Translation Lookaside Buffer (TLB) invalidation and cache invalidation.

Context Switch Anatomy:

  1. Save Hardware Context: General-purpose registers (RAX, RBX, etc.), instruction pointer (RIP), stack pointer (RSP), and floating-point/SIMD registers are saved onto the task's kernel stack.
  2. Scheduler Decision: The scheduler picks the next runnable task from the runqueue.
  3. Switch Virtual Memory (Process switch only): If switching between different processes, the MMU's page table base register (CR3 in x86_64) is updated to point to the new process's PML4 root. This flushes non-global TLB entries (or switches PCID - Process-Context Identifiers).
  4. Switch Kernel Stack & Registers: The kernel changes the active stack pointer and loads the registers of the incoming task.
  5. Direct vs Indirect Cost: Direct cost is ~1–2 microseconds (register swap + kernel code). The indirect cost is 10–100× worse: cold L1/L2 CPU caches and TLB misses that stall CPU pipelines for thousands of clock cycles as memory lines are refetched from RAM.
Q03
Apple Amazon Synchronization
Why are spinlocks disastrous in single-CPU user-space applications, and when is a spinlock preferred over a mutex in the kernel?
Show Answer ▾
Direct Takeaway A spinlock polls the lock continuously in a busy loop using atomic operations (e.g. compare_and_swap). On a single CPU, spinning starves the thread holding the lock from ever getting CPU time to release it.

Rules for Spinlocks:

  • Kernel Interrupt Context: Mutexes put the calling thread to sleep (state TASK_UNINTERRUPTIBLE), triggering a scheduler context switch. In an interrupt handler (Top Half), the kernel cannot sleep or yield the CPU! Therefore, interrupt handlers must use spinlocks (specifically spin_lock_irqsave).
  • Hold Time Threshold: A spinlock is only preferred when the expected lock holding time is shorter than two context switches (~2–4 microseconds). If the critical section performs I/O or takes long, a mutex is mandatory.
  • User-space Pitfall: If Thread 1 acquires a spinlock and gets preempted by the OS scheduler, Thread 2 will burn 100% of its CPU quantum spinning uselessly until Thread 1 is rescheduled.
Q04
Google Microsoft Kernel Internals
How does a Linux futex (Fast Userspace Mutex) achieve near zero-overhead locking in the uncontended case?
Show Answer ▾
Direct Takeaway A futex is an integer in userspace memory. In uncontended scenarios, acquisition and release are handled entirely in user space using atomic CPU instructions (e.g., lock cmpxchg) with zero syscall overhead. The kernel is only invoked via the futex() syscall when contention occurs.

Execution Path:

  • Fast Path (No Contention): Thread A uses an atomic instruction to change the 32-bit integer from 0 to 1. Success! Cost: ~10 nanoseconds (just cache-line arbitration).
  • Slow Path (Contention): Thread B tries to atomically claim the lock and fails. It issues syscall(SYS_futex, &uaddr, FUTEX_WAIT, 1, ...). The kernel verifies the value hasn't changed and enqueues Thread B onto a kernel wait queue, putting it to sleep.
  • Unlock: Thread A atomically decrements the integer. If it detects waiting threads, it calls FUTEX_WAKE to wake the sleeping thread.
Q05
Netflix Meta Concurrency
Explain the Readers-Writers problem. How do you prevent Writer Starvation in high-concurrency systems?
Show Answer ▾
Direct Takeaway In a read-preferring lock, new readers are granted access as long as at least one reader is active. Under constant read traffic, a writer will starve indefinitely. Writer-preference locks prevent this by blocking new readers once a writer has queued.

Implementation Strategy:

  • Maintain three counters: active readers, queued readers, and queued writers.
  • When a writer requests the lock, set a writer_waiting flag. All subsequent read requests must wait on a condition variable, even if current readers are still finishing.
  • In the Linux kernel, RCU (Read-Copy-Update) is used extensively instead of RW locks. Readers execute lock-free with zero overhead, while writers make a private copy, update it, atomically swap the pointer, and wait for a "grace period" before freeing old memory.
Q06
OpenAI Google Hardware & Memory
What is False Sharing, how does the MESI protocol cause cache line bouncing, and how do you fix it in high-performance code?
Show Answer ▾
Direct Takeaway False sharing occurs when two independent threads on different CPU cores modify completely separate variables that happen to reside on the same 64-byte CPU cache line.

The MESI Protocol Mechanism:

  • CPUs fetch and invalidate memory in 64-byte chunks called cache lines. The MESI protocol states are Modified, Exclusive, Shared, and Invalid.
  • Core 1 modifies variable a. The cache coherence bus invalidates Core 2's cache line containing b.
  • Core 2 now misses on b and writes to it, invalidating Core 1's cache line. The cache line bounces between L1 caches over the interconnect bus, destroying throughput.
  • Fix: Pad data structures so that concurrently written variables reside on separate cache lines (e.g. alignas(64) in C++11, @Contended in Java).
Q07
Apple Amazon Deadlocks
State the 4 Coffman conditions for Deadlock. Why is Banker's Algorithm impractical for modern production operating systems?
Show Answer ▾
Direct Takeaway Deadlock occurs if and only if all four conditions hold: 1) Mutual Exclusion, 2) Hold and Wait, 3) No Preemption, 4) Circular Wait. Banker's Algorithm is impractical because processes cannot know their maximum future resource claims in advance.

Coffman Conditions & Production Reality:

  • Circular Wait Prevention: The most effective production solution is strict global lock ordering (acquire Lock A before Lock B everywhere in the codebase).
  • Why Banker's fails in real OSes: It requires $O(M \times N^2)$ matrix operations on every single allocation request, assumes a fixed number of processes, and assumes processes state their maximum allocation ahead of time (impossible when users run arbitrary programs). Real OSes use lock-ordering invariants (verified by tools like Linux lockdep) and timeouts.
Q08
Anthropic Meta Real-Time Scheduling
What is Priority Inversion? How did it nearly abort NASA's Mars Pathfinder mission, and how does Priority Inheritance solve it?
Show Answer ▾
Direct Takeaway Priority Inversion occurs when a low-priority task holds a resource needed by a high-priority task, but the low-priority task is preempted by medium-priority tasks, effectively preventing the high-priority task from making progress.

Mars Pathfinder War Story:

  • Low-priority meteorological task acquired a shared data bus mutex.
  • High-priority attitude control task needed the bus and blocked waiting for the mutex.
  • Medium-priority communications task preempted the low-priority task (since medium > low). The low-priority task could not finish, so the high-priority task missed its deadline, triggering watchdog resets.
  • Priority Inheritance Protocol: When a high-priority task blocks on a mutex held by a lower-priority task, the lower-priority task temporarily inherits the high priority until it unlocks the mutex, preventing medium tasks from preempting it.

Q10
Meta Amazon Process Management
What are Zombie and Orphan processes? What system resources do zombies consume, and how does PID 1 clean them up?
Show Answer ▾
Direct Takeaway A Zombie is a process that has terminated, but whose parent has not yet called wait()/waitpid(). An Orphan is a process whose parent exited before it; it is adopted by PID 1 (init or systemd).

Zombie Resource Impact:

  • Zombies consume zero CPU and zero RAM (their memory pages, stack, and heap have already been deallocated).
  • However, they retain an entry in the kernel's process table (`task_struct`), holding onto a **Process ID (PID)**.
  • If a buggy parent program continuously spawns children without reaping them, it can exhaust the system's PID table (/proc/sys/kernel/pid_max, typically 32,768 or 4,194,304), preventing any new process from starting on the server!
  • Reaping: When a parent dies, all its children are reparented to PID 1. PID 1 runs an infinite loop calling wait() to reap zombies automatically.

2. virtual memory & address translation (q11 – q20)

Q11
OpenAI Google Address Translation
Walk through a 64-bit virtual memory address translation on x86_64 across a 4-level page table.
Show Answer ▾
Direct Takeaway x86_64 uses 48-bit canonical virtual addresses divided into four 9-bit indices and a 12-bit physical page offset: PML4 $\to$ PDP $\to$ PD $\to$ PT $\to$ Physical Frame + Offset.

Bit Breakdown (48-bit Canonical Virtual Address):

  • Bits [47:39] (9 bits): Page Map Level 4 (PML4) index ($2^9 = 512$ entries).
  • Bits [38:30] (9 bits): Page Directory Pointer (PDP) index.
  • Bits [29:21] (9 bits): Page Directory (PD) index.
  • Bits [20:12] (9 bits): Page Table (PT) index.
  • Bits [11:0] (12 bits): Page Offset ($2^{12} = 4096$ bytes = 4KB page).

The CPU uses the physical address in the CR3 register to find PML4, indexes down each level, and extracts the physical page frame address, adding the 12-bit offset. Without the TLB, every single memory access would require 5 RAM reads!

Q12
Meta Anthropic Page Faults
Differentiate between Minor Page Faults, Major Page Faults, and Invalid Faults (Segmentation Faults).
Show Answer ▾
Direct Takeaway A Minor fault resolves in RAM without disk I/O. A Major fault requires reading from disk/swap (costing milliseconds). An Invalid fault accesses unmapped memory, resulting in SIGSEGV.
  • Minor Page Fault (Soft Fault): The page is already in physical RAM (e.g. shared library loaded by another process, or freshly allocated zero-filled page by malloc). The kernel just updates the page table entry (PTE). Cost: ~1 microsecond.
  • Major Page Fault (Hard Fault): The page must be fetched from disk (file-backed mmap or swapped-out memory). The thread is put to sleep while disk DMA fetches the 4KB block. Cost: ~1–10 milliseconds (HDD) or 10–50 microseconds (NVMe SSD).
  • Invalid Fault (SIGSEGV): The address is not in any allocated Virtual Memory Area (VMA), or permissions are violated (e.g. write to read-only code). The kernel delivers signal 11 (`SIGSEGV`).
Q13
Apple Netflix Memory Allocation
How does malloc(100) vs malloc(100MB) behave? How much physical memory is allocated at the moment of malloc()?
Show Answer ▾
Direct Takeaway malloc() allocates ZERO bytes of physical RAM! It only updates the virtual memory map. Physical RAM is allocated lazily on the first write via demand-paging page faults.

Small vs Large Allocations:

  • Small (< 128KB): Handled via brk() / sbrk(). Extends the top of the process heap segment. Managed in user space by arena buckets to minimize syscall overhead.
  • Large (≥ 128KB): Allocated via mmap(MAP_ANONYMOUS | MAP_PRIVATE). Creates a new independent memory mapping outside the heap. When free() is called, memory is immediately released back to the OS via munmap(), preventing heap fragmentation.
Q14
NVIDIA Google HugePages & TLB
What is the Translation Lookaside Buffer (TLB)? Why do databases and LLM training pipelines mandate HugePages (2MB / 1GB)?
Show Answer ▾
Direct Takeaway The TLB is an on-chip associative cache of recent virtual-to-physical address translations. HugePages (2MB or 1GB instead of 4KB) reduce the number of TLB entries needed by up to 500×, preventing TLB thrashing on large datasets.

The Math of TLB Reach:

  • A typical L1 TLB has 64 to 128 entries. With 4KB pages, 64 entries cover only $64 \times 4\text{KB} = 256\text{KB}$ of memory!
  • If a database (e.g. PostgreSQL, Redis) or an AI model buffer has 64GB of memory, accessing random memory addresses causes constant TLB misses (each costing 4 RAM reads to walk the page table).
  • With 2MB HugePages, 64 TLB entries cover $64 \times 2\text{MB} = 128\text{MB}$ (a 512× improvement). One page table level (PT) is skipped entirely, making walks faster.
Q15
Amazon Microsoft Page Replacement
What is Belady's Anomaly? Which page replacement algorithms suffer from it, and why doesn't LRU?
Show Answer ▾
Direct Takeaway Belady's Anomaly is the phenomenon where giving a process MORE physical page frames causes MORE page faults. It occurs in FIFO, but is mathematically impossible in LRU and Optimal replacement.

Stack Algorithms:

  • An algorithm is a stack algorithm if the set of pages in memory for $N$ frames is always a strict subset of the pages that would be in memory for $N+1$ frames.
  • LRU (Least Recently Used) and Optimal are stack algorithms: adding a frame never evicts a page that would have been kept with fewer frames.
  • FIFO is not a stack algorithm: the oldest page inserted is evicted regardless of whether it is heavily referenced, causing counter-intuitive fault spikes on specific reference strings (e.g. 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5).
Q16
Google Apple Virtual Memory
What is Memory Thrashing? How does the OS detect it, and what is the Working Set Model?
Show Answer ▾
Direct Takeaway Thrashing happens when the total working sets of active processes exceed available physical RAM, causing the OS to spend more time swapping pages to/from disk than executing user instructions.

The Working Set Theory (Peter Denning):

  • The Working Set $W(t, \Delta)$ is the set of unique pages referenced by a process in the last $\Delta$ time units.
  • If $\sum |W_i| > \text{Total Physical RAM}$, thrashing begins immediately. CPU utilization drops because all processes are blocked waiting for I/O page reads.
  • OS Mitigation: The OS must suspend (swap out entirely) one or more processes to free frames for the remaining processes, letting them finish their working sets.
Q17
OpenAI Meta Copy-On-Write
How does Copy-On-Write (COW) work under the hood during fork()? What hardware flag triggers the page duplication?
Show Answer ▾
Direct Takeaway fork() duplicates the parent's page table entries without copying any physical memory frames, marking all shared pages as Read-Only. The first write attempt triggers a Page Fault, allowing the kernel to duplicate only that specific 4KB page.

Step-by-step Execution:

  1. Parent calls fork(). Kernel creates child's mm_struct and points page table entries to the parent's existing physical frames.
  2. Kernel clears the Write Bit (R/W = 0) in the Page Table Entries of both parent and child.
  3. Either process attempts to write to a variable: CPU MMU triggers a Page Fault (fault code: write to read-only page).
  4. The kernel inspects the VMA, sees the page is marked COW: allocates a brand-new 4KB physical frame, copies the original data, points the faulting process's PTE to the new frame, sets R/W = 1, and resumes execution.
Q18
Netflix Anthropic Linux Kernel
How does the Linux Out-of-Memory (OOM) Killer choose which process to terminate? What is oom_score_adj?
Show Answer ▾
Direct Takeaway The OOM killer selects the process that frees the maximum RAM with the least collateral damage based on a calculated oom_score (0 to 1000). System services protect themselves using oom_score_adj.

OOM Scoring Algorithm:

  • Base score is roughly proportional to percentage of physical RAM consumed: points = (RSS + swap) * 1000 / total_ram.
  • Processes running as root or with high CPU run times get minor discounts.
  • oom_score_adj (-1000 to +1000): Users/orchestrators adjust priorities. A value of -1000 disables OOM killing completely for that process (e.g. sshd, kubelet). A positive value (e.g. +500) makes batch workers sacrificed first.
Q19
NVIDIA Microsoft Hardware Architecture
What is NUMA (Non-Uniform Memory Access), and how does NUMA node affinity impact multi-GPU AI clusters?
Show Answer ▾
Direct Takeaway In NUMA systems, memory access time depends on memory location relative to the processor. Accessing local memory attached to the CPU socket is 2–3× faster than accessing remote memory across the interconnect bus (UPI / Infinity Fabric).

Impact on AI & GPU Training:

  • In dual-socket servers, GPU 0–3 are wired to Socket 0's PCIe root complex; GPU 4–7 are wired to Socket 1.
  • If a PyTorch data loader thread runs on Socket 1 but feeds GPU 0 (Socket 0), every tensor transfer crosses the slow CPU-to-CPU inter-socket link, cutting PCIe DMA throughput in half.
  • Fix: Bind processes using numactl --cpunodebind=X --membind=X or set CPU core affinity to the PCIe root complex of the assigned GPU.
Q20
Apple Amazon Kernel Memory
Compare Internal vs External Fragmentation. How do the Linux Buddy Allocator and SLAB/SLUB allocators solve them?
Show Answer ▾
Direct Takeaway External fragmentation is free memory broken into small scattered holes. Internal fragmentation is allocated memory larger than requested. Linux uses the Buddy Allocator for page frames and SLAB/SLUB for byte-sized kernel objects.

Two-Tier Allocator Design:

  • Buddy Allocator: Manages physical pages in power-of-two blocks ($2^0, 2^1, ..., 2^{10}$ pages). Solves external fragmentation by merging adjacent free "buddies" into larger contiguous blocks upon deallocation.
  • SLAB / SLUB Allocator: Sits on top of the buddy allocator. Frequently allocated kernel structs (e.g. task_struct, inode, dentry) have fixed sizes. SLAB creates dedicated pre-allocated object pools, eliminating internal fragmentation and constructor overhead.

3. syscalls, scheduling & linux kernel (q21 – q30)

Q21
Google Meta Syscall Mechanics
Trace the execution path of a system call from user-space assembly into Ring 0 kernel execution.
Show Answer ▾
Direct Takeaway The user program loads the syscall number into the RAX register, sets argument registers, and executes the syscall assembly instruction, transitioning hardware from Ring 3 to Ring 0.

Step-by-step Trace on x86_64:

  1. Setup: User C library (glibc) places syscall ID into RAX, and args into RDI, RSI, RDX, R10, R8, R9.
  2. Instruction: glibc executes syscall. Hardware switches privilege mode bit (Ring 3 $\to$ Ring 0), saves RIP into RCX, saves RFLAGS into R11, and loads the kernel entry point from Model-Specific Register (MSR_LSTAR).
  3. Stack Swap: Kernel executes swapgs to load kernel per-CPU data and switches the stack pointer RSP to the process's kernel stack.
  4. Dispatch: Kernel indexes the sys_call_table[RAX] and executes the C implementation (e.g. sys_read()).
  5. Return: Result is stored in RAX; kernel executes sysretq to restore Ring 3 and user registers.
Q22
Anthropic OpenAI Kernel Optimization
What is the vDSO (Virtual Dynamic Shared Object), and how does it make gettimeofday() 100× faster?
Show Answer ▾
Direct Takeaway vDSO maps a read-only page of kernel memory containing real-time clock data directly into user space, allowing syscalls like clock_gettime() to execute as ordinary function calls without entering Ring 0.

Why It Matters:

  • A traditional syscall involves CPU privilege switches, pipeline flushes, and register saves (~50–100 nanoseconds).
  • Microservices and AI logging systems call time functions millions of times per second.
  • The kernel exports a page containing timer calibration data and maps it into every ELF process. The C library simply reads the CPU's invariant Time Stamp Counter (RDTSC) and performs math in user space (~1–3 nanoseconds).
Q23
Meta Google CPU Scheduling
How does the Linux CFS (Completely Fair Scheduler) select the next task to run? Explain vruntime and Red-Black trees.
Show Answer ▾
Direct Takeaway CFS tracks each task's virtual runtime (vruntime) and always selects the task that has received the least CPU time (the leftmost node in an augmented Red-Black tree).

The CFS Math:

  • $$vruntime \mathrel{+}= \Delta \text{exec\_time} \times \frac{\text{NICE\_0\_LOAD}}{\text{task\_weight}}$$
  • Tasks with higher priority (lower nice value) have greater weight, so their $vruntime$ advances more slowly, giving them proportionally more CPU time.
  • Data Structure: Tasks are ordered in a Red-Black Tree by $vruntime$. Finding the next task is $O(1)$ (cached pointer to leftmost node). Re-inserting an executed task is $O(\log N)$.
Q24
Netflix Apple CPU Scheduling
What is the Convoy Effect in CPU scheduling? How does Round Robin solve it, and what are the tradeoffs of the time quantum?
Show Answer ▾
Direct Takeaway The Convoy Effect occurs in FCFS when short I/O-bound tasks get stuck behind a long CPU-bound task, leaving I/O devices idle and spiking latency. Round Robin mitigates this with preemptive time slicing.

Time Quantum ($q$) Tradeoffs:

  • Quantum too large ($q \to \infty$): Degenerates into FCFS, reintroducing the Convoy Effect and poor interactive responsiveness.
  • Quantum too small ($q \to 0$): Context switch overhead dominates. If $q = 1\text{ms}$ and context switch is $0.2\text{ms}$, 17% of total CPU capacity is wasted on scheduler bookkeeping.
  • Production Sweet Spot: Typically 10ms to 100ms in general-purpose operating systems, dynamically scaled by CFS.
Q25
Amazon Microsoft Kernel Architecture
Compare Monolithic Kernels (Linux) vs Microkernels (Mach, seL4). Why did Linux win the performance battle for cloud servers?
Show Answer ▾
Direct Takeaway Monolithic kernels run all OS subsystems (FS, drivers, networking, memory) in Ring 0 in a single shared address space. Microkernels run only scheduling and IPC in Ring 0, pushing drivers and filesystems to Ring 3 user space.

The IPC Bottleneck:

  • In a microkernel, a simple read() request requires multiple message passes and context switches: App $\to$ Kernel $\to$ FS Server $\to$ Kernel $\to$ Disk Driver $\to$ Kernel $\to$ App.
  • In Linux, a read() is a single function call inside Ring 0. Linux won on bare-metal throughput and latency, although microkernels remain popular in mission-critical safety systems (automotive, aerospace, Apple secure enclave).
Q26
Apple Google Interrupts
What are Top Halves vs Bottom Halves (softirqs, tasklets, workqueues) in Linux interrupt handling?
Show Answer ▾
Direct Takeaway The Top Half runs immediately with interrupts disabled to acknowledge hardware, while the Bottom Half defers expensive packet processing or disk parsing to run asynchronously with interrupts re-enabled.

Bottom Half Flavors:

  • Top Half (Hard IRQ): Runs in interrupt context, cannot sleep. Must be under a few microseconds (e.g. read NIC register, reset hardware interrupt line, enqueue pointer).
  • SoftIRQ: Runs concurrently on multiple CPUs, cannot sleep. Used for high-throughput networking (e.g. TCP/IP stack) and block storage.
  • Workqueue: Runs in a regular kernel thread (kworker) context. Can sleep, block, and allocate memory. Used for heavy background tasks.
Q27
OpenAI Anthropic CPU Affinity
How does CPU Affinity (sched_setaffinity) prevent cache invalidation, and when is core pinning essential for AI inference?
Show Answer ▾
Direct Takeaway CPU affinity binds a process/thread to specific CPU cores, preventing the scheduler from migrating the thread across cores and invalidating warm L1/L2 caches.

Performance Wins in AI Inference:

  • When a thread migrates from Core 0 to Core 8, its working memory must be re-fetched from L3 cache or remote RAM, spiking tail latency (p99).
  • In high-throughput LLM engines (vLLM, TensorRT-LLM), background worker threads, tokenizers, and NCCL communication threads are pinned to dedicated physical cores on the same NUMA node as the GPU to prevent jitter and thread migration stalls.
Q28
NVIDIA Meta Real-Time Linux
How do Linux real-time scheduling policies (SCHED_FIFO, SCHED_RR) work, and how can an unprivileged process cause a system freeze?
Show Answer ▾
Direct Takeaway Real-time tasks have static priorities (1 to 99) and will ALWAYS preempt any normal CFS task. A SCHED_FIFO task in an infinite loop will completely starve all normal user and system processes.

Safety Protections:

  • SCHED_FIFO: Runs until it voluntarily yields, blocks on I/O, or is preempted by a higher-priority RT task.
  • SCHED_RR: Same as FIFO, but preempted when its time slice expires if another task of identical priority is waiting.
  • Throttling Protection: Linux includes /proc/sys/kernel/sched_rt_runtime_us (default 950,000 $\mu$s per 1,000,000 $\mu$s), reserving 5% of CPU time for normal tasks so an admin can log in via SSH to kill a runaway RT process.
Q29
Microsoft Amazon Hardware & Power
Explain CPU C-States vs P-States. How does aggressive power management cause p99 latency spikes in high-frequency trading and low-latency APIs?
Show Answer ▾
Direct Takeaway C-states are CPU sleep states (C0 = active, C6 = deep sleep). P-states are operating frequencies (voltage/clock scaling). Waking from deep C-states takes 10–50 $\mu$s, causing latency spikes for sporadic requests.

Latency Anatomy:

  • When a core is idle between requests, the kernel governor puts it into C6 (flushing caches and cutting core voltage).
  • When a new network packet arrives, the CPU takes tens of microseconds just to power back up to C0.
  • Low-Latency Tuning: Ultra-low-latency servers disable deep C-states entirely using kernel boot parameters processor.max_cstate=1 intel_idle.max_cstate=1 idle=poll and lock the CPU governor to performance.
Q30
Google Netflix Security & Silicon
What were Meltdown and Spectre? How did hardware speculative execution break OS kernel memory protection?
Show Answer ▾
Direct Takeaway Meltdown allowed user-space code to read kernel memory by exploiting out-of-order execution before privilege checks completed, transmitting secrets via cache side-channels.

Mechanism & Mitigation:

  • A user program accesses kernel memory: val = *kernel_address; access(probe_array[val * 4096]);.
  • The CPU speculatively executes the second instruction before the MMU privilege violation terminates the process. Even though the instruction is rolled back, probe_array[val * 4096] remains cached in L1 cache!
  • The attacker measures memory read times of probe_array to deduce the secret kernel byte.
  • OS Fix: KPTI (Kernel Page Table Isolation) completely separates user and kernel page tables, unmapping kernel memory while running in user space (at the cost of a 5–20% performance hit on older CPUs).

4. storage, fast i/o & inter-process communication (q31 – q40)

Q31
Netflix Google I/O Multiplexing
Why is epoll O(1) while select() and poll() are O(N)? Explain the internal data structure of epoll.
Show Answer ▾
Direct Takeaway select and poll require copying an array of file descriptors to the kernel on every call and linearly scanning all $N$ descriptors. epoll registers descriptors once in a kernel Red-Black tree and uses an interrupt-driven Ready List for $O(1)$ event retrieval.

The Three epoll Syscalls & Structures:

  • epoll_create1(): Allocates an epoll instance containing an augmented Red-Black Tree (for tracking monitored FDs) and a doubly linked Ready List.
  • epoll_ctl(): Adds/modifies/deletes monitored FDs ($O(\log N)$ in the RB-tree). The kernel registers a callback with each socket's wait queue.
  • epoll_wait(): When an NIC receives packets for a socket, its callback places that socket into the Ready List. epoll_wait() simply copies the Ready List to user space ($O(\text{ready})$), completely independent of total connections ($N$).
Q32
OpenAI Meta epoll Modes
Explain Edge-Triggered (EPOLLET) vs Level-Triggered epoll. Why is non-blocking I/O mandatory with Edge-Triggered mode?
Show Answer ▾
Direct Takeaway Level-Triggered reports an event as long as data remains in the buffer. Edge-Triggered reports an event ONLY when state transitions from empty to non-empty (rising edge).

Why Non-Blocking Sockets are Mandatory:

  • With Edge-Triggered mode, if you read 1KB from a 4KB buffer, epoll_wait() will never notify you again for the remaining 3KB until new bytes arrive!
  • Therefore, you must loop read() until it returns EAGAIN or EWOULDBLOCK.
  • If the socket is blocking, that final read() will block the worker thread forever, hanging the server!
Q33
Amazon Anthropic Zero-Copy
Trace the complete data path of serving a static file via read()+write() vs sendfile() (Zero-Copy).
Show Answer ▾
Direct Takeaway read() + write() requires 4 context switches and 4 data copies (2 through CPU). sendfile() requires 2 context switches and zero CPU copies (pure DMA).

Data Path Comparison:

  • Traditional read() + write():
    1. Disk $\xrightarrow{\text{DMA}}$ OS Page Cache (Kernel) [Switch 1: User $\to$ Kernel]
    2. OS Page Cache $\xrightarrow{\text{CPU copy}}$ User Buffer (App memory) [Switch 2: Kernel $\to$ User]
    3. User Buffer $\xrightarrow{\text{CPU copy}}$ Socket Buffer (Kernel) [Switch 3: User $\to$ Kernel]
    4. Socket Buffer $\xrightarrow{\text{DMA}}$ Network Card (NIC) [Switch 4: Kernel $\to$ User]
  • sendfile() / splice(): Data moves directly from Page Cache to NIC ring buffer via DMA with SG-DMA (Scatter-Gather). CPU never touches the bytes!

What is io_uring in modern Linux? How does it outperform epoll for mixed disk and network workloads?
Show Answer ▾
Direct Takeaway io_uring uses two lockless ring buffers (Submission Queue and Completion Queue) shared between kernel and user space via mmap(), allowing asynchronous I/O with zero syscalls in polling mode.

Key Architecture Advantages:

  • Kernel Polling (IORING_SETUP_SQPOLL): A kernel thread continuously polls the Submission Queue. User space writes I/O requests directly to the ring buffer with memory barriers—submitting millions of IOPS without a single syscall!

What is an Inode in Unix/Linux? Why doesn't an inode store the filename, and how do hard links vs soft links differ?
Show Answer ▾
Direct Takeaway An Inode stores all file metadata (size, permissions, timestamps, block pointers) EXCEPT the filename. Filenames are stored in directory entries (dentry) mapping names to Inode numbers.

Hard Links vs Symbolic (Soft) Links:

  • Hard Link: A new directory entry pointing to the exact same Inode number. Increments the Inode's reference counter (nlink). Deleting one link does not delete data until nlink == 0. Cannot span across different filesystems.
  • Soft Link: A standalone file with its own unique Inode whose content is the path string of the target file. Can cross filesystems and can become dangling/broken if the target is moved.

OpenAI Google IPC
Benchmark IPC mechanisms: Pipes vs Unix Domain Sockets vs POSIX Shared Memory vs TCP Loopback. Which has the lowest latency?
Show Answer ▾
Direct Takeaway POSIX Shared Memory is by far the fastest (~100 nanoseconds) because it requires zero kernel copies. Unix Domain Sockets (~2–5 $\mu$s) outperform TCP loopback (~10–20 $\mu$s) by skipping the TCP stack.
  • POSIX Shared Memory: After initial setup via shm_open() and mmap(), communication happens directly through shared RAM addresses with no kernel involvement. Synchronization requires user-space atomics or futexes.
  • Unix Domain Sockets: Bypasses TCP checksumming, flow control, and IP routing tables. Performs a single kernel-space memory copy between socket buffers.
  • TCP Loopback (127.0.0.1): Traverses the entire network stack, calculating checksums, allocating sk_buff structs, and handling TCP ACK state machines.

How does Unix Domain Socket file descriptor passing (SCM_RIGHTS) enable zero-downtime hot reloading of web servers?
Show Answer ▾
Direct Takeaway sendmsg() with SCM_RIGHTS allows a running server process to transfer listening socket file descriptors across processes without closing them or dropping incoming TCP client connections.

Hot-Reload Sequence (e.g. Nginx, Envoy):

  1. Process A is serving traffic on port 443 (FD 4).
  2. Process B (new binary) is started.
  3. Process A opens a Unix Domain Socket to Process B and sends FD 4 using SCM_RIGHTS control message.
  4. The kernel clones the open file table reference into Process B's file descriptor table. Process B begins accepting connections immediately on the same port!
  5. Process A drains its in-flight connections gracefully and exits cleanly. Zero dropped packets!

Apple Microsoft File Descriptors
Explain the three-tier file structure: File Descriptor Table vs Open File Table vs Inode Table. What happens across fork() and exec()?
Show Answer ▾
Direct Takeaway File Descriptor Table is per-process; Open File Table is system-wide (tracking file offset and flags); Inode Table is system-wide (tracking physical file metadata).
  • Across fork(): The child receives a duplicate FD table, pointing to the same Open File Table entries. Crucial detail: if child seeks to offset 100, the parent's file offset moves to 100 too!
  • Across exec(): The FD table is preserved UNLESS the file descriptor has the FD_CLOEXEC (close-on-exec) flag set, in which case the kernel closes it before loading the new binary.
Q40
Amazon Netflix Journaling File Systems
Explain the 3 Ext4 Journaling modes (data=journal, data=ordered, data=writeback). How do they balance crash consistency vs write throughput?
Show Answer ▾
Direct Takeaway data=journal writes both data and metadata to the journal first (safest, slowest). data=ordered (default) writes data to storage before committing metadata to journal. data=writeback offers maximum speed with no ordering guarantees.
  • data=journal: Every byte is written twice (first to journal ring buffer, then to main file system). Cuts write performance in half.
  • data=ordered (Ext4 Default): Only metadata is journaled, but the kernel guarantees that data blocks are written to disk BEFORE metadata commits. Prevents "garbage data" leaks upon crash.
  • data=writeback: Metadata is journaled, but data can be written anytime. High throughput, but upon crash, recently appended files may contain stale deleted data from old blocks.

Meta Google Cgroups
How do Cgroups (Control Groups v1 vs v2) enforce CPU quotas and memory limits? What triggers a container OOM kill?
Show Answer ▾
Direct Takeaway While Namespaces govern what a container can SEE, Cgroups govern how much resources it can USE. CPU is throttled via CFS quotas; exceeding memory.max triggers cgroup OOM termination.

Mechanisms in Production:

  • CPU Throttling: Governed by cpu.cfs_quota_us and cpu.cfs_period_us. If quota is 200,000 $\mu$s and period is 100,000 $\mu$s, the container is allocated 2 full CPU cores. If it exceeds quota within a period, the kernel CFS deschedules all threads until the next period.
  • Container OOM Killer: When a container hits memory.max, the kernel tries page reclaim. If insufficient RAM is freed, the OOM killer kills the highest-scoring task *inside that cgroup*, leaving the host server completely untouched.

Netflix Google Production Triage
Your production server has 99% CPU utilization in %si (SoftIRQ) or %wa (I/O Wait). How do you isolate the root cause in 60 seconds?
Show Answer ▾
Direct Takeaway High %si indicates a network packet flood or interrupt storm; high %wa indicates processes blocked waiting for disk/NFS operations.

  1. If high %si: Check cat /proc/softirqs to see which subsystem is firing (NET_RX vs BLOCK). If NET_RX is spiking on a single core, inspect ethtool -S <eth0> and balance Receive Side Scaling (RSS) queues.

  4. Run vmstat 1 5: check si/so (swap in / swap out). If non-zero, memory exhaustion is forcing constant swapping.

OpenAI NVIDIA AI Infrastructure
In high-throughput LLM inference engines (e.g. vLLM), why does KV-cache memory fragmentation mandate PagedAttention, and how does it mirror OS virtual memory?
Show Answer ▾
Direct Takeaway Traditional LLM serving pre-allocates contiguous GPU VRAM for the maximum possible sequence length (e.g. 8K tokens), wasting 60–80% of VRAM due to internal and external fragmentation. PagedAttention mirrors OS virtual memory by partitioning the KV cache into non-contiguous physical memory blocks.

The Direct Operating System Parallel:

  • The OS Analogy: Just as the OS kernel uses Page Tables to map contiguous Virtual Memory addresses to non-contiguous 4KB Physical RAM frames, vLLM maintains a Block Table mapping logical token positions to non-contiguous 16-token GPU memory blocks.
  • Dynamic Allocation: As the LLM generates tokens during decoding, new physical memory blocks are allocated on demand (demand paging).
  • Copy-on-Write for Parallel Sampling: Multiple candidate branches in beam search or parallel sampling share the prompt's KV cache blocks via reference counting, duplicating only when modified—identical to Linux fork() Copy-On-Write!
