breaking the wall of memory isolation — pipes, shared memory, unix domain sockets, and signals.

the 30-second elevator pitch

The operating system goes to extraordinary lengths to isolate processes: the MMU prevents Process A from reading a single byte of Process B's memory. But what if Process A is a web scraper and Process B is an AI analyzer? They must collaborate. Inter-Process Communication (IPC) refers to the kernel-provided mechanisms that allow isolated processes to exchange data and synchronize actions safely.

  • The Speed vs Convenience Spectrum:
    • Pipes & Sockets: Easiest to use, automatic synchronization, but data is copied through kernel buffers.
    • Shared Memory: Fastest IPC in existence (zero copies, native RAM speeds), but you must manually handle synchronization using mutexes or semaphores.
🧷 the fundamental ipc taxonomy
1. Data Transfer: Pipes, FIFOs, Message Queues, Sockets (data is moved via kernel buffers).
2. Shared Memory: Processes map the exact same physical RAM frames into their address spaces.
3. Signaling: Asynchronous software interrupts delivering an integer signal code (e.g. SIGINT).

ipc mechanisms compared

1. Anonymous Pipes

Created with pipe(int fds[2]). Unidirectional byte stream connected between related processes (parent and child).

  • Implemented as an in-memory 64 KB circular ring buffer in kernel RAM.
  • Automatic blocking: Reader blocks if empty; writer blocks if buffer is full (flow control).
  • Limitation: Half-duplex. Only processes sharing ancestry via fork() can use them (e.g. ls | grep foo).

2. Named Pipes (FIFOs)

Created via mkfifo /tmp/myfifo. Extends pipes to totally unrelated processes.

  • Appears as a special file in the directory tree with an Inode.
  • Zero Disk I/O: The filesystem entry is merely an access handle. All data flows strictly through the kernel's in-memory buffer!
  • Persists until deleted with rm.

3. POSIX Shared Memory

Created with shm_open() and mmap().

  • The Speed King: Reading/writing takes 0 nanoseconds of kernel overhead. Both processes read and write directly to physical memory.
  • The Catch: No automatic synchronization! If both processes write simultaneously, data corrupts. Requires POSIX named semaphores.

4. Unix Domain Sockets (UDS)

Socket communication using the AF_UNIX address family.

  • Uses standard socket API (connect, accept, send, recv).
  • Supports both stream (TCP-like) and datagram (UDP-like) modes with reliable, in-order delivery.
  • Crucial Feature: Can pass open file descriptors across processes via SCM_RIGHTS!

⚠️ magic trick: passing file descriptors across processes
In high-availability web servers (like Nginx zero-downtime binary reloads) or container runtimes, Process A needs to hand an active, listening network socket over to Process B.
You cannot simply send the integer int fd = 4 over a pipe! File descriptor integers are strictly local to a process's private FD table. Integer 4 in Process B points to something completely different or nothing at all.
The Fix: Send the socket using a Unix Domain Socket with sendmsg() and control message SCM_RIGHTS. The kernel intercepts the message, looks up the real struct file in the system open-file table, creates a new entry in Process B's FD table, and hands Process B a valid descriptor pointing to the exact same underlying connection!

signals: asynchronous software interrupts

A Signal is an asynchronous notification delivered by the kernel to a process to notify it of an event:

  • SIGINT (2): Ctrl+C in terminal. Graceful interrupt.
  • SIGTERM (15): Default termination request. Can be caught and handled for graceful cleanup.
  • SIGKILL (9): Immediate termination. Cannot be caught, blocked, or ignored! The kernel deletes the process PCB instantly.
  • SIGSEGV (11): Segmentation violation (illegal memory access).
  • SIGCHLD (17): Sent to parent whenever a child process terminates or stops (used to reap zombies).

the danger of async-signal-safe functions

⭐ why malloc() and printf() inside signal handlers will hang your server
A signal can arrive at any instruction boundary.
Suppose Thread 1 is inside malloc() and has acquired the internal glibc heap lock. Right at that microsecond, a SIGINT arrives. The CPU pauses Thread 1 and immediately jumps to your custom signal handler function.
If your signal handler calls printf() or malloc(), it will attempt to acquire the exact same heap lock! Because Thread 1 already holds it and is paused, the signal handler deadlocks with itself! The process hangs forever.
Production Rule: Inside signal handlers, only call async-signal-safe functions (e.g. raw write() syscall, or set a volatile sig_atomic_t flag = 1; and exit).

real-world case study: google chrome's multi-process architecture

Before Chrome (2008), browsers ran all tabs as threads in a single process. If one bad JavaScript loop or flash plugin crashed on Tab 8, your entire browser with all 20 tabs died instantly!

  • Chrome's Architecture:
    • Browser Process: Manages UI, address bar, network requests, and disk cache. Runs with full user privileges.
    • Renderer Processes: One process per tab/site. Executes HTML parsing, CSS styling, and V8 JavaScript. Runs inside a strict OS Sandbox (zero direct disk, network, or device access!).
    • GPU Process: Isolates graphics drivers.
  • The IPC Glue: Sandboxed renderer processes cannot write to disk or open network sockets. When JavaScript calls fetch(), the renderer sends an IPC message over a Unix Domain Socket / Mojo IPC channel to the Browser process. The privileged Browser process executes the network I/O and streams the response bytes back into the renderer's memory via Shared Memory!

quick check

  • Which IPC mechanism provides the highest throughput and lowest latency? Shared Memory.
  • Why does a Unix Domain Socket outperform a localhost TCP connection? It bypasses the entire TCP/IP networking stack (checksums, sequencing, flow control) and copies data directly between kernel buffers.
  • Can a process catch or ignore `SIGKILL`? No. SIGKILL and SIGSTOP are handled directly by the kernel and cannot be intercepted.

the 20-second summary

Inter-Process Communication circumvents process memory isolation to enable distributed teamwork. Pipes and message queues provide synchronized streams through kernel memory, while Shared Memory offers zero-overhead data transfer requiring manual semaphore synchronization. Unix Domain Sockets deliver 2x the throughput of localhost networking while enabling file descriptor passing, and signals provide lightweight asynchronous interrupts that require strictly reentrant, signal-safe handlers.
